# iOS parity API audit

Baseline: Android v0.1.1 (578a502); iOS deployment floor 16; checked against Xcode 26.6 / iOS 26.5 headers and Apple documentation. These are source/availability findings, not device evidence. See the [event inventory](parity-inventory.md) for units, lifetime, privacy, owners and test scenarios.

| Android behavior | Public iOS route | Gap / acceptance test |
| --- | --- | --- |
| Session, item, buffering and terminal error observation | Existing AVPlayer/AVPlayerItem observation, host preparation/render hooks and access logs | Run local and HLS lifecycle traces. Ready-for-display is not a rendered-frame timestamp. |
| Per-resource transfer and load errors | [AVMetrics](https://developer.apple.com/videos/play/wwdc2024/10113/) HLS resource events, iOS 18+; [transaction metrics](https://developer.apple.com/documentation/avfoundation/avmetricmediaresourcerequestevent) supply available network timing; legacy item error log is a different source | Correlate each segment and its transaction, exclude cache hits, and validate byte counts, cancellation and retries. iOS 16/17 event-level equivalence and callback coverage unproven. |
| Cumulative bandwidth observation | [AVPlayerItemAccessLogEvent](https://developer.apple.com/documentation/avfoundation/avplayeritemaccesslogevent): observed bitrate is throughput; indicated bitrate is advertised stream bitrate | Report independently and deduplicate cumulative snapshots. Neither field proves access to the internal AVPlayer ABR estimate. Negative means unavailable. |
| Dual EWMA, startup threshold and confidence | Pure Swift port of Android algorithm; accepts bytes and monotonic milliseconds | Verify shared vectors from pinned Kotlin implementation; session confidence resets independently of meter estimate. |
| Custom estimate drives variant selection | [preferredPeakBitRate](https://developer.apple.com/documentation/avfoundation/avplayeritem/preferredpeakbitrate) is a preference; use host opt-in and [variant switch events](https://developer.apple.com/documentation/avfoundation/avmetricplayeritemvariantswitchevent) to measure the effect | Same multi-variant profile with/without host policy, compare selected variants on hardware. Public setter alone does not meet parity. Native estimate, full switch reasons and time-to-first-byte estimator remain open. |
| Available and selected formats | AVURLAsset variants / AVAssetTrack format descriptions, plus iOS 18+ successful variant switch events | Track available, selected and inferred states separately. Test all three variants and stale-event rejection; do not equate rendition identity with a causal switch reason. |
| Decoder catalog, active decoder name, implementation, initialization and capabilities | VideoToolbox's [VTIsHardwareDecodeSupported](https://developer.apple.com/documentation/videotoolbox/vtishardwaredecodesupported(_:)) checks a codec type, not the active AVPlayer decoder. The installed iPhoneOS VideoToolbox headers do not declare VTCopyVideoDecoderList. | Independently verify format metadata and codec support. Active decoder identity, initialization time, catalog, instance limits, alignments, tunneled/secure/adaptive flags and supported ranges stay open; do not infer from codec support. |
| FairPlay request lifecycle, retry, timing and failure | [AVContentKeySessionDelegate](https://developer.apple.com/documentation/avfoundation/avcontentkeysessiondelegate) provides request/renewal/failure callbacks; host measures license HTTP attempts | Authorized FairPlay playback and server fixture required; never intercept or copy SPC, CKC, keys, raw identifiers or credentials. Provisioning equivalence is open. |
| Key status, expiration, security level, current/max HDCP | Request status is not key validity. External protection state callback is iOS 17.4+; [player output obscuration](https://developer.apple.com/documentation/avfoundation/avplayer/isoutputobscuredduetoinsufficientexternalprotection) is a Boolean | Do not map coarse protection to numeric HDCP. Key validity, expiry (apart from validated server-supplied data), security classification and both HDCP measurements require independent proof. |
| Storage/analytics/UI/ABR Explorer | Platform-independent state and persistence contracts; native host UI; Android reader accepts only schema v2 | Verify fixture-based bidirectional codecs, bounded queue and atomic writes, and presentation from shared event traces. Views cannot close rows with absent underlying signals. |

Use a hardware test to classify a route as verified. Unsupported, unverified and unavailable signals stay open in the parity checklist.
